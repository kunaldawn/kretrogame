# The Windows DLLs the player's Wine keeps when the whitelist is enforced.
#
# Off by default. `make runtime PLAYER_DLL_WHITELIST=1` turns it on, and then
# every *.dll under Wine's i386-windows and x86_64-windows trees, and in the
# prefix template's system32 and syswow64, that is named neither here nor in
# runtime/loaddll/*.txt is removed. Executables, drivers (.drv, .sys), codecs
# (.acm) and control panels are never touched: wineboot, services, winedevice
# and explorer are the prefix's skeleton, and all of them together are small.
#
# It is off because a list is only as good as the games that were run to make
# it, and dropping a DLL costs whichever game needed it without saying so. The
# way to grow it is to play a game with WINEDEBUG=+loaddll and hand the log to
# runtime/loaddll-whitelist.sh, which writes runtime/loaddll/<name>.txt. The
# conservative default - runtime/player-prune.txt - removes only tools and
# never a DLL.
#
# One name per line, a shell glob matched case-insensitively against the
# file's basename.
# This file is the floor: what Wine itself needs to start a process, draw a
# window and make a sound, and what the era's games load for graphics, audio,
# input, video and networking, in both architectures.
